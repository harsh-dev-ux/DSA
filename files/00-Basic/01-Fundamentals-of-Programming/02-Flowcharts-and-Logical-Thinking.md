# Flowcharts and Logical Thinking

Before writing any code, you should plan what you're gonna do. A **flowchart** is basically a visual diagram that maps out the steps to solve a problem — think of it like a blueprint before building a house.

Flowcharts use a few basic symbols:
- **Oval** — Start/End of the program
- **Rectangle** — A process or action (like "calculate sum")
- **Diamond** — A decision/question (yes or no, always has two paths)
- **Parallelogram** — Input/Output (reading data from user or showing results)
- **Arrows** — Connect everything, show the flow direction

Three main patterns you'll see:
1. **Sequential** — steps go one after another, no branching (e.g. read two numbers → add them → print result)
2. **Conditional** — has a decision point that splits into different paths (e.g. is age >= 18? yes → eligible, no → not eligible)
3. **Loop** — repeats steps until a condition is met (e.g. print numbers 1 to 10)

**Pseudocode** is another way to plan — it's like writing your logic in plain English that looks kinda like code but isn't actual code. Flowcharts are more visual, pseudocode is more text-based. Both work, use whatever helps you think.

The approach for any problem: understand what's needed → break it into small steps → draw it out → test with examples → then code it.
